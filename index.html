02Cara Identifikasi Visual

Di CTF, kita tidak selalu tahu enkoding apa yang dipakai. Ini cara membaca ciri-cirinya dengan cepat:

📌 Urutan cek yang efisien

1. Cek charset dulu → 2. Cek panjang / padding → 3. Coba decode → 4. Hasil valid?

Jika hasil decode masih berisi karakter printable, kemungkinan besar berhasil dan ada layer berikutnya.

Encoding Ciri Visual Utama Ciri Negatif (eliminasi)
Base16 Hanya 0-9 dan A-F / a-f. Panjang selalu genap. Terasa "lebih panjang 2×". Tidak ada huruf G–Z, tidak ada karakter spesial.
Base32 Hanya huruf kapital A-Z dan angka 2-7. Sering diakhiri === atau ======. Tidak ada angka 0, 1, 8, 9. Tidak ada huruf kecil.
Base64 Campuran huruf kecil & besar + angka + +/. Diakhiri = atau ==. Tidak ada karakter aneh seperti ! < >.
Base85 (Py) Ada karakter ! < > ^ * &. Terasa lebih "berantakan". Tidak ada = padding. Tidak ada spasi.
ASCII85 Ada karakter # ) * + _ ~. Mirip base85 tapi berbeda distribusi. Versi Adobe diawali <~ dan diakhiri ~> — tapi versi Python tidak.

💡 Cara membedakan Base85 vs ASCII85

Keduanya pakai 85 karakter dari ASCII 33–117, tapi dengan mapping yang berbeda. Artinya charset-nya identik, tapi urutan/nilai per karakternya beda. Kamu harus coba keduanya dan lihat mana yang menghasilkan output valid (printable).

Di Python: base64.b85decode() untuk base85, base64.a85decode() untuk ascii85.

04Kenapa Urutannya Bisa Berbeda-beda?

Ini bagian yang paling penting untuk dipahami. Enkoding dilakukan secara acak — artinya setiap kali challenge ini di-generate, urutannya bisa berbeda.

🎲 Randomisasi = Tidak ada urutan "benar" yang tetap

Soal menyebut "15 kali secara acak". Artinya script pembuat challenge memanggil random.choice(['base64','base32','base16','base85','ascii85']) sebanyak 15 kali dan menerapkannya bertumpuk.

Jadi file yang kamu terima bisa saja berbeda dari file orang lain yang mendownload challenge yang sama di waktu berbeda!

Kenapa harus brute-force semua kemungkinan?

Karena tidak ada header/marker yang menunjukkan "ini base64" atau "ini base32". Satu-satunya cara adalah:

  1. Coba decode dengan semua metode yang mungkin
  2. Filter hasil yang "masuk akal" (>90% karakter printable)
  3. Rekursif lakukan hal yang sama pada setiap hasil valid
  4. Berhenti saat menemukan string REDLIMIT{

Kenapa DFS (Depth-First) bukan BFS?

Secara teori BFS lebih aman (tidak akan stuck di path salah). Tapi di challenge ini DFS langsung berhasil di percobaan pertama karena:

  • Hanya satu path yang valid sampai kedalaman 15 — encoding yang salah hampir pasti menghasilkan output binary/non-printable
  • Setiap decode yang "berhasil" (printable) memang selalu merupakan encoding valid karena data aslinya memang encoded text
  • Tidak ada "false positive path" yang panjang

Kenapa ukuran berkurang setiap layer?

Karena kita sedang mendecode (mengurai), bukan encode. Setiap encoding menambah ukuran, jadi setiap decode menguranginya. Lihat pola di trace:

19735 → 15788 → 11840 → 5920 → 3700 → 2960 → 1480 → 740 → 592 → 296 → 185 → 148 → 118 → 59 → 47 → 37

Dari 19.735 karakter → 37 karakter (flag). Setiap layer encoding memang menambah overhead ukuran.

05Script Solver

Script ini menggunakan DFS rekursif — mencoba semua metode decode di setiap level dan melanjutkan hanya jika hasilnya valid (printable).

import base64

def try_decode(data):
    """Coba semua metode decode, return list (method, result)"""
    results = []
    if isinstance(data, str):
        data = data.encode('latin-1')

    # Base16 — hanya 0-9 A-F, panjang output = 2x input
    try:
        results.append(('base16', base64.b16decode(data.upper())))
    except: pass

    # Base32 — hanya A-Z 2-7, padding kelipatan 8
    try:
        pad = len(data) % 8
        if pad: data_p = data + b'=' * (8 - pad)
        results.append(('base32', base64.b32decode(data_p.upper())))
    except: pass

    # Base64 — A-Z a-z 0-9 +/, padding kelipatan 4
    try:
        pad = len(data) % 4
        if pad: data_p = data + b'=' * (4 - pad)
        results.append(('base64', base64.b64decode(data_p)))
    except: pass

    # Base85 (Python) — ASCII 33-117, encode 4 byte → 5 char
    try:
        results.append(('base85', base64.b85decode(data)))
    except: pass

    # ASCII85 — charset sama tapi mapping berbeda dari base85
    try:
        results.append(('ascii85', base64.a85decode(data, adobe=False)))
    except: pass

    return results

def is_valid(data):
    """Cek apakah hasil decode berupa teks yang bisa dibaca"""
    try:
        text = data.decode('utf-8')
    except:
        try: text = data.decode('latin-1')
        except: return False
    ratio = sum(1 for c in text if c.isprintable()) / len(text)
    return ratio > 0.9  # >90% printable = valid

def solve(data, depth=0, path=[]):
    """DFS rekursif — coba decode sampai ketemu flag"""
    text = data.decode('utf-8', errors='replace') if isinstance(data, bytes) else data
    if 'REDLIMIT{' in text:
        print(f"✅ FLAG: {text}")
        print(f"Path: {' → '.join(path)}")
        return True
    if depth > 20: return False

    for method, decoded in try_decode(data):
        if is_valid(decoded):
            if solve(decoded, depth+1, path+[method]):
                return True
    return False

with open('output.txt') as f:
    solve(f.read().strip())
